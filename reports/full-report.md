## 6. 2025-11-02 以降に改正・更新された法令

### API の仕様で確かめたこと

`lawapi-v2.yaml` version 2.1.139 で確かめた。

- `/laws`(法令一覧)には、改正日や更新日で絞る引数がない。あるのは `asof`(時点)、`promulgation_date_from/to`(その法令自体の公布日)、`amendment_law_id` など。
- `/law_revisions/{law_id_or_num}`(改正履歴)には `amendment_date_from/to`(改正法令施行期日)、`amendment_promulgate_date_from/to`、`updated_from/to`(データの更新日)、`repeal_date_from/to` がある。ただし `law_id_or_num` が必須なので、**法令を指定せずに「この日以降に改正された法令」を一度に取る手段はない**。
- 一括ダウンロードの「最新の更新法令データ」(`file_section=3&update_date=YYYYMMDD`)は、仕様に「取得範囲は過去３ヶ月」とある。作業日(2026-11-18)から見て 2025-11-02 は範囲の外なので使えない。
- 履歴の `updated` 項目の説明は「正誤等による更新日時」。

そこで 2,981 法令それぞれの履歴を 1 回ずつ取り(`16_fetch_revisions.py`、2,981 件すべて 200)、手元で日付を絞った。履歴は全部で 30,924 件。

### 結果

手続の数は、その法令を根拠にする R7 の行数。

| 条件(2025-11-02 以降、その日を含む) | 法令 | 手続 |
|---|---:|---:|
| (1) 施行期日がこの日以降の改正履歴がある | 1,337 | 51,543 |
| うち施行済み(UnEnforced でない)の履歴がある | 1,250 | 48,119 |
| うち未施行(UnEnforced)の履歴がある | 486 | 29,885 |
| (1b) 施行期日が空の未施行履歴 | 0 | 0 |
| (2) 改正法令の公布日がこの日以降 | 1,105 | 41,093 |
| (3) `updated` がこの日以降 | 1,338 | 50,118 |
| (4) 廃止日がこの日以降 | 15 | 238 |
| (1)〜(4) のいずれか | 1,366 | 52,156 |

- 「施行済み」と「未施行」の両方の履歴がある法令があるので、(1) の内訳の和は (1) と一致しない。
- (3) の `updated` は、改正版が新しく載った日と、正誤だけの更新日とを区別できない。正誤だけの更新が何件あるかは分からない。
- 検算として、一覧を asof=2025-11-01 と現時点(2026-11-18 取得)の 2 回取り、law_revision_id が違う法令を数えた。1,251 法令 / 48,149 手続だった。(1) の施行済みと比べると、両方に入る 1,249、一覧の比較だけ 2、履歴だけ 1。2 件と 1 件の中身は調べていない。
- 法令ごとの一覧は `out/updated_laws.csv`、履歴の全件は `out/law_revisions.csv`。

## 7. 分からないこと・限界

- **条・項・号が無い理由**: 4 節のとおり、一つ一つは確かめていない。
- **改正後の版での照合**: 調査票の条項号が 2025-11-01 時点で正しいかだけを見た。改正後の版でも同じ条を指すかは見ていない。
- **法令IDが決まらない 526 行**: 改正法の附則(「…の一部を改正する法律附則」)、告示・基準、旧規則などが多い。改正法・告示が e-Gov API でどこまで取れるかは確かめていない。一覧を `mission=Partial` で引くと 0 件だった(試行)。
- **準用する側の条**: 準用の行は準用される側だけを照合した。準用する側の条があるかは見ていない。
- **列挙**: 2 つ目以降の項・号は照合していない。
- **`関連条項号`・`関連する根拠法令`の列**: 今回は照合していない。
- **年間件数**: 空欄が 27,238 行ある。空欄が「件数 0」なのか「把握していない」なのかは、調べていない(調査票の解説 PDF では、この点を確かめていない)。
