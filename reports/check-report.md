## 1. 「無くなった」353 行の行き先

前回、2026-11-18 の版で同じ番号の条・項・号が見つからなかった行を「無くなった」とした。その 353 行について、同じ法令の中に、元の文言と同じか近い要素があるかを探した。

- 対象: 353 行。異なる要素で 277、法令 64。
- 候補: 2026-11-18 の版の同じ法令の中で、深さが同じ要素すべて。条なら条、項なら項、号なら号。本則と制定附則を含む。
- 比べる文言:
  - 番号は除いた。条名(第N条)、項番号、号名(一、二…)。番号が変わっても同じ文言とみなせるようにするため。
  - 空白・改行も除いた。
  - ルビの読みは、前回と同じく除いている。

### 近さの基準

近さは Python の `difflib.SequenceMatcher(autojunk=False).ratio()` で測った。

- 値は 2 × 一致した字数 ÷ (両方の字数の和) で、0〜1。1.000 は文言が同じ。
- 計算を省くため、文字数の比と `quick_ratio` で見た上限が 0.60 に届かない候補は、近さを計算していない。

| 判定 | 基準 |
|---|---|
| **移った** | 最も近い候補の近さが **0.90 以上**。移った先はその候補の番号 |
| **消えた** | 最も近い候補でも近さが **0.60 未満** |
| **判定できない** | 次のどれか |
| | ・最も近い候補が 0.60 以上 0.90 未満 |
| | ・0.90 以上の候補が複数あり、最良と 2 番目の差が 0.01 未満 |
| | ・最良の候補と同じ番号の要素が旧版にもあり、近さ 0.90 以上だった。つまり、もともと似た文言の要素で、移ったとは言えない |
| | ・元の文言が 10 字未満 |
| | ・本文が取れない |

0.90 と 0.60 は、私が決めた値です。点検の結果を見て見直す前提です。

#### 注意

- 「移った」は、文言が近い要素が別の番号にある、という意味でしかない。法令上の移動(繰上げ・繰下げ)だと確かめたわけではない。改正法の本文は見ていない。
- 「消えた」は、同じ深さの要素の中に近い文言がない、という意味。次の場合も「消えた」に入る。
  - 文言が大きく書き換わった
  - 深さが変わった(項が独立の条になった、など)
  - 本則・制定附則以外の場所へ移った
- 全行は `out/moves.csv` にある。移った先、近さ、2 番目の近さ、元の文言、移った先の文言の列を含む。

## 2. 点検用の抜き取り `review-sample.csv`

種は 20261118 で、pandas の `sample(random_state=20261118)` を使った。

| 区分 | 母数 | 抜き取り | 法令の数 |
|---|---:|---:|---:|
| 文言が変わった | 2,737 | 30 | 28 |
| 文言が同じ | 44,196 | 30 | 28 |
| 無くなった→移った | 155 | 10 | 10 |
| 無くなった→消えた | 112 | 10 | 9 |
| 計 | | 80 | |

### 列

区分、手続ID、手続名、法令ID、法令名、条項号、e-Gov URL、2025-11-01 の文言、2026-11-18 の文言、比べた深さ、移った先、近さ、備考。

- 頼まれた 8 列に、区分・比べた深さ・移った先・近さ・備考を足した。
- 条項号は調査票の原文のまま。
- e-Gov URL は `https://laws.e-gov.go.jp/law/{法令ID}`(法令ページ)。
- 文言は区分によって形が違う。違いは備考の列にも書いた。
  - 「変わった」「同じ」: 照合した深さの要素の全文。番号を含み、空白・改行を除いている。
  - 「移った」「消えた」: 1 節で比べた形。番号と空白・改行を除いている。
    - 「移った」の 2026-11-18 の文言は、移った先の要素のもの。
    - 「消えた」の 2026-11-18 の文言は空。
- 文字コードは UTF-8(BOM 付き)。Excel でそのまま開けるようにするため。
- 「文言が同じ」でも、条まで照合した行は条全体を比べている。中身の確かめにはならないが、比べ方が正しいかを点検するために入れた。

## 3. 一括ダウンロードの更新データを 1 回だけ試した

### 呼び出し

`https://laws.e-gov.go.jp/bulkdownload?file_section=3&update_date=20261117&only_xml_flag=true`

- 日付は、作業日 2026-11-18 の前日の 2026-11-17 にした。
- 呼んだのは 1 回だけ。応答は `data/bulk/20261117/download.bin` に保存した。中身の展開はしていない。

| 項目 | 値 |
|---|---|
| 状態 | 200(`application/octet-stream`、zip) |
| 大きさ | 691,069 バイト |
| 取得にかかった時間 | 0.8 秒 |
| zip の中身 | `R081117.csv` 1 つと、版ごとのフォルダに入った XML 18 個 |

### 取れたもの

zip の中の `R081117.csv` が、更新された法令の一覧になっている。

- **18 行、法令ID 8。** すべて府省令で、未施行(○)の行は 6。
- 列: 法令種別、法令番号、法令名、法令名読み、旧法令名、公布日、改正法令名、改正法令番号、改正法令公布日、施行日、施行日備考、法令ID、本文URL、未施行。
- 1 行が 1 つの版にあたる。本文URL が版ごとの URL になっている。

### 手元のデータとの突き合わせ

R7 で使う 2,981 法令に入るのは **6 法令** で、それを根拠にする R7 の行は **150**。

| 法令ID | 法令名 | R7 の行 |
|---|---|---:|
| 323M40000100034 | 医療情報基盤・診療報酬審査支払機構法施行規則 | 1 |
| 327M50000100032 | 母体保護法施行規則 | 12 |
| 357M50002040001 | 労働金庫法施行規則 | 29 |
| 419M60000100129 | 高齢者の医療の確保に関する法律施行規則 | 52 |
| 423M60000100144 | 特定Ｂ型肝炎ウイルス感染者給付金等の支給に関する特別措置法施行規則 | 11 |
| 430M60001FCA001 | 産業競争力強化法施行規則 | 45 |

- CSV の 18 版のうち、手元の改正履歴(2026-11-18 の未明から朝に取得)にあるのは 12 版。残りの 6 版がなぜないのかは分からない。取得の時刻の差かもしれないが、確かめていない。
- 参考として、手元の改正履歴で `updated` が 2026-11-17 の版は 20、法令は 7。CSV の 18 行・8 法令とは数が合わない。`updated`(正誤等による更新日時)と、一括ダウンロードの「更新日」が同じ意味かは分からない。

### 毎週の追跡に使うための材料

分かったこと:

- 1 日分は 1 回の呼び出しで取れる。今回は 0.8 秒・約 0.7 MB だった。
- 1 週間分なら 7 回の呼び出しになる。中の CSV に法令ID・版・施行日・未施行の印があるので、R7 の法令ID と突き合わせれば、根拠にする手続を出せる。
- 2,981 法令の改正履歴を毎回取る方法は、前回 3,384 秒かかった。それに比べると呼び出しはずっと少ない。
- 仕様書によれば、取れるのは過去 3 か月だけ。間が 3 か月を超えると取りこぼす。
- XML の本文も一緒に入っているので、文言の比べもできそうに見える。中身はまだ読んでいない。

分からないこと(1 回しか試していないため):

- 試したのは 1 日分だけ。日によって件数や大きさがどう変わるか、更新のない日に何が返るかは見ていない。
- 「更新日」が、データが載った日なのか、ほかの日付なのかは仕様書に書かれていない。
- この一覧が、その日の更新をすべて含むのかは確かめていない。手元の改正履歴とは版の数が合わない(上記)。
- 法令API の `updated_from` を使うと結果がどうなるかとの比べもしていない(法令ごとの呼び出しになるため)。
